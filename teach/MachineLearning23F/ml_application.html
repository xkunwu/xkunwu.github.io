从哪里开始

本项目分为个人基础任务与小组自选项目，用四周完成一次可解释、可重复的机器学习实验。基础任务每人独立提交；自选项目每组选一个题目和一条主路线；普通CPU即可完成必做部分。第一次可以下载数据或模型，无需购买API或GPU。请围绕自己的兴趣或实际问题自主选题。文中的七题用于说明不同任务的实施方法，可按需参考；单车和房价涉及表格处理，迁移学习和检索涉及模型下载。

你需要回答：输入是什么、预测什么、怎样判断效果、结果能用于什么条件。示例：用一套房屋的面积等已知属性预测售价；售价不能同时出现在输入中。分类预测类别，回归预测数值，检索返回相关条目的排序。

基础任务：个人完成

解压后，找到包含README.md的ml_application文件夹。打开终端（Windows可用Anaconda Prompt），用cd命令进入该文件夹；这里称为工作目录，后续相对路径都从这里查找。若已经进入，不必再次执行cd ml_application。只需Python 3.8或以上及标准库，无需安装任何包。

cd ml_application
python basic/student_template.py --check
python basic/run_checks.py --submission basic/student_template.py

命令中的python启动Python解释器，后面的.py文件是要运行的程序；–check是传给程序的选项。代码中TODO表示需要补全的位置，NotImplementedError表示该部分尚未实现。–check只验证解释器和入口，TODO尚未完成时算法检查失败属正常。依次补全squared_distance、predict_one、count_correct。点用两个整数构成的列表表示，如[3,4]；a[i]表示第i项，索引从0开始。平方距离为两坐标差的平方之和：[0,0]与[3,4]得到9+16=25，无需开平方。遍历训练点，保留最小距离及对应标签；相等时保留先出现者。最后逐位置比较预测与真实标签，累计相等次数。

JSON是一种用字段名表示数据的文本格式，例如{“op”:“distance”}中op是字段名、distance是字段值；列表用方括号表示。标准输入是程序接收输入的通道，标准输出是程序返回结果的通道，本地通常对应终端。程序每次从标准输入读取一行JSON，输出一行紧凑JSON；不要向标准输出增加提示。op=distance时输入a、b，输出整数距离；op=predict时输入x（训练点列表）、y（对应类别）、query，输出类别；op=count输入predictions、labels，输出正确数；op=classify输入x、y、queries、labels，输出predictions与correct两个字段。输入输出示例见basic/examples中的成对.in与.out文件。可运行以下命令，应输出25。

python basic/student_template.py < basic/examples/01.in

有效输入约定：坐标为-100至100整数，标签为0至99整数；训练点1至20个，查询1至20个，所有对应列表等长，点均为二维。count允许空列表，结果0。平台每例输入输出均不超过2000字符。每例独立启动，无文件读写、网络或第三方依赖。

平台评分规则见《机器学习综合训练-任务书及评分标准》“评分标准”章。提交补全后的单文件，不提交本地运行器。教师完整实现不向学生分发。

基础题分阶段操作

三个函数写在同一份basic/student_template.py中，不拆成多个提交文件。先不运行完整流程，逐步检查：

  1. 距离阶段（distance）：补全squared_distance，按坐标累计平方差。[0,0]到[3,4]应为25。
  2. 预测阶段（predict）：补全predict_one，保留最近训练点的类别；单训练点查询应返回该点标签。
  3. 统计阶段（count）：补全count_correct；三项全对返回3，空列表返回0。
  4. 联调阶段（classify）：不新增函数，用已提供的入口连接预测与统计；公开例两条预测[0,1]，正确2条。

例如先运行：

python basic/run_checks.py --stage distance --submission basic/student_template.py

依次将distance换为predict、count、classify。最后去掉–stage运行全部公开例。阶段检查只执行声明范围；初期其余TODO尚未实现不会影响当前函数检查。

手工核验预测：训练点[-1,0]类别7、[1,0]类别3，查询[0,0]与两点平方距离都是1，应选择先出现的类别7。不要以类别数字大小作为平局规则。预测标签应取train_y[最近位置]，不能误返回位置本身。位置从0起，位置不等于类别。

输入输出示例（各一行）：

{"op": "classify", "x": [[0,0], [3,3]], "y": [0,1], "queries": [[0,1], [3,2]], "labels": [0,1]}
{"predictions":[0,1],"correct":2}

自动评阅精确比较紧凑JSON，保留已提供的序列化代码及字段顺序；仅补全三个函数。输入非法时提供代码会报错，但正式用例均符合约定。count最多20项。外部平台不提供输入文件，通过标准输入给出JSON；本地的重定向符号“<”只是模拟同一过程。

材料清单注明已提交的基础题文件，平台提供提交标识时可记录。无需为基础题另写长报告，也无需导出平台不存在的文件。理解题：距离最小为何无需开平方？自查：非负数开平方保持大小顺序，平方距离选出的最近点相同。

基础任务通过仅证明标准库运行正常。自选项目需另装对应依赖，从发布包根目录运行：

python -m pip install -r requirements.txt

PyTorch路线另装requirements-torch.txt，预训练检索路线另装requirements-retrieval.txt。intro.py用于理解第三方库的训练与预测流程，不作为基础任务提交。详见本任务书“项目共同知识与排错”一节。建议自选项目使用Python 3.11独立环境，基础题仍只需标准库。

四周操作安排

  • 第一周：个人基础题、选题、读数据和划分。检查运行入口、数据形状及样本标识不重叠。
  • 第二周：简单规则参照与第一个学习模型。仅拟合训练数据，在验证集记录指标。
  • 第三周：两个有目的的改动。先写假设，再记录参数、验证结果与解释。
  • 第四周：固定方案、最终测试与报告。保存真实输出，从提交目录重新运行。

训练集用于学习；验证集用于选择参数和方法；测试集用于最终估计泛化效果。不要反复查看测试分数后改模型。预处理也只能在训练集拟合，参见官方说明。时间数据按先后划分；重复样本不能横跨划分。

多数类预测和训练目标均值是简单参照，不是完成机器学习项目的替代。超参数是训练前选择的配置，如正则强度或隐藏层宽度。每次改动先写原因，只改变少量条件；效果下降也需要如实记录。

回归MAE为绝对误差的平均值，RMSE为平方误差均值的平方根，均越小越好。分类精确率表示预测为正的样本中有多少确实为正，召回率表示真正为正的样本找回多少；F1是二者的调和平均，分母为零时明确记0。类别不均衡时不能只看准确率。Recall@3是前三项中命中相关项的查询比例（本任务每条查询一个相关FAQ）；MRR是首个相关项排名倒数的平均值，未找到记0。

自主确定项目

优先选择自己希望解决的问题。第一周在报告第一部分写出：谁在什么情境下需要结果；输入是什么；输出是什么；数据从哪里取得；准备采用什么机器学习方法；用什么指标判断是否有效；现有设备与时间能否支持。教师据此提供反馈，无需另交申请表。

例如“预测价格”还不够明确，可以写成“根据公开房屋记录中的面积、房龄等信息预测售价，用保留样本上的平均绝对误差评价”。这是问题表述示例，不要求选择房价题。

自拟项目可使用自己的代码目录和运行入口，无需符合参考模板的函数或文件结构。报告中的命令统一从ml_application根目录开始。方法和工具按问题选择，不要求同时使用传统模型和神经网络。完成简单参照、初始方案与至少两个有依据的改动或对照，再用事先保留的数据做最终评价。评价结果未提高时，保留真实结果并解释原因。

附录

项目共同知识与排错

所有命令在ml_application根目录执行。基础题无需安装下述依赖；自选项目建议独立Python 3.11环境。先运行python –version，再执行python -m pip install -r requirements.txt；PyTorch另装requirements-torch.txt，预训练文本检索另装requirements-retrieval.txt。安装CPU版本即可，具体系统安装方法参考PyTorch官网。不要为了基础题安装这些库。

从一条样本理解数据

样本是一条记录。特征X是预测时已经知道的信息，标签y是希望预测的答案。表格X形状(n,d)表示n条记录、每条d个特征；标签通常是(n,)。例如面积和房龄可以作特征，售价是标签；不能把答案再放进特征。分类预测有限类别，回归预测数字，检索返回候选条目排序。

训练集用于学习参数；验证集用于选择方法、超参数；测试集只在方案固定后最终评估。标准化、填补、词表也会学习统计量，因此只能在训练集fit，再对其余数据transform。Pipeline串联这些步骤。重复记录跨集合会夸大效果；按重复组划分或先去重。时间题按日期先后，不能随机打乱。

标准化对每列减训练均值，再除训练标准差。数值缺失可用训练中位数填补。独热编码将类别变为0/1位置，陌生类别要能处理。对单个未见类别崩溃不是有效的预测流程。

评价与改动

多数类预测或训练目标均值是简单参照。先让一个学习器运行，再每次只改少量条件，写出“为什么可能有帮助”。不能为了好看的分数换测试集。准确率=正确数/总数；混淆矩阵行是真实类别、列是预测。精确率看预测正类是否可靠，召回率看真实正类是否找全，F1是二者调和平均，零分母记0。MAE是绝对误差平均，RMSE是平方误差平均后开根。比较必须使用相同数据和同一种指标。

PyTorch：张量是可计算的多维数组。批次是一次参与更新的一小组样本。网络输出与标签计算损失；zero_grad清除旧梯度，backward计算当前梯度，step更新参数。分类CrossEntropyLoss接收logits，不要先做softmax；验证时eval并no_grad，防止推理行为错误或意外累积梯度。CPU小模型够用，不要求CUDA。

retrieval参考项目操作

从ml_application根目录执行，先读本任务书“项目共同知识与排错”一节。安装依赖：

python -m pip install -r requirements-retrieval.txt

projects/retrieval/data提供30条人工教学FAQ与60条改写查询。faq.json每条含id、question、answer；queries.json含question、relevant_id、split。dev用于改进，test用于最终评价；按FAQ标识分离查询，但统一候选库有意保留全部FAQ。它是教学语料，不是真实质量基准。正式项目需额外编写独立查询并说明标注依据。

  1. 运行以下命令，应显示30条FAQ、60条查询；框架检查标识与划分，无需编写模型。

    python projects/retrieval/project.py --stage data

  2. 补全rank_questions(corpus, queries, method)，返回每条查询对应的全部FAQ标识列表，按相似度降序。函数收到查询文本，不收到正确标注。tfidf分支使用TfidfVectorizer(analyzer=‘char’, ngram_range=(1,2))；仅在候选FAQ问题fit，查询transform，再点积得到相似度。不要用答案字段或relevant_id直接排序。

  3. embedding分支加载sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2，device=‘cpu’，encode(…, normalize_embeddings=True)后点积。归一化使向量长度为1，点积等于余弦相似度。模型卡见官方页面。首次下载所需网络、磁盘及时间应实际记录。

  4. hybrid分支组合两种相似度，如各占一半；先在开发查询验证其假设。排序平局按FAQ原顺序。运行以下命令，在runs/retrieval/dev.json记录三个方案的指标和排序。

    python projects/retrieval/project.py --stage compare

  5. 固定方案后运行以下命令，结果保存test.json。Recall@3为前三项命中查询比例；MRR为首个相关项排名倒数的平均。排名从1开始，没有相关项记0。报告以开发选定的方法作为最终方案，其余测试结果仅作预先声明的对照，不能再据此选择。

    python projects/retrieval/project.py --stage final

至少分析三条失败查询，不足则全部：区分同义词、措辞歧义和标注问题。冻结文本编码器也是机器学习方法，但不能写成自己训练了大模型。CPU可完成，禁止为了本题强制购买API。
